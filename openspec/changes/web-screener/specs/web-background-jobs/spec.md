## Purpose

管理網站上需要較長時間的選股與回測請求，讓 HTTP 請求可快速取得工作識別碼，並能安全查詢進度、取消工作及辨識程序重啟造成的中斷。

## ADDED Requirements

### Requirement: 建立及查詢計算工作
網站 SHALL 以工作識別碼建立選股或回測工作，並提供工作狀態、進度、結果摘要、完整結果與錯誤的查詢 API；工作紀錄及成功結果 SHALL 持久化於應用程式 SQLite。成功結果 SHALL 最多保留最近 20 個已完成工作；清除較舊結果時 SHALL 保留可查詢的工作狀態。

#### Scenario: 建立選股或回測工作
- **WHEN** 使用者提交通過驗證的選股或回測請求
- **THEN** API 立即回傳唯一工作識別碼，工作於背景執行且可輪詢狀態

#### Scenario: 查詢工作進度
- **WHEN** 使用者以工作識別碼查詢執行中的工作
- **THEN** 回應包含工作種類、狀態、目前階段及可用進度/摘要

#### Scenario: 取得完成結果
- **WHEN** 使用者查詢仍在保留範圍內的已完成工作結果
- **THEN** API 回傳該工作的選股或回測完整結果，且不重新執行工作

#### Scenario: 結果已超過保留數量
- **WHEN** 使用者查詢已超過最近 20 個完成工作保留範圍的結果
- **THEN** API 回報結果已過期，並保留可辨識的工作狀態

### Requirement: 計算工作的互斥與取消
系統 SHALL 同時間只執行一個長時間工作，並提供取消可取消工作的操作；取消 SHALL 保留已完成資料且不得偽裝成成功完成。

#### Scenario: 工作執行時建立另一工作
- **WHEN** 另一個長時間工作已在執行，使用者建立新的計算工作
- **THEN** 系統拒絕新工作並回報目前工作識別碼或忙碌狀態

#### Scenario: 取消可取消工作
- **WHEN** 使用者取消仍在執行的選股或回測
- **THEN** 回測在單次核心呼叫中於最多十個交易日的檢查點取消；選股可在計算區塊邊界取消。系統丟棄不完整的計算結果並回報取消狀態

### Requirement: 重啟後辨識未完成工作
Web 服務啟動時 SHALL 將前次程序留下的所有非終態工作（等待、執行中及取消中）標記為中斷，不得呈現為成功或自動重新執行。

#### Scenario: Web 程序於工作未完成時重啟
- **WHEN** 工作紀錄仍為等待、執行中或取消中時 Web 服務重新啟動
- **THEN** 該工作狀態轉為中斷，使用者可重新送出工作但舊工作不會被誤報為成功或永久停留在等待
