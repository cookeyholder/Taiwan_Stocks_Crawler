## Purpose

讓個人使用者能在瀏覽器設定既有選股策略、查看符合標的與原因，並從結果進入個股分析頁，不必在桌面版和網站間切換。

## ADDED Requirements

### Requirement: 網站策略選股
API 與網站 SHALL 提供 `StrategyKind` registry 中的布林擠壓、均線交叉、RSI、均線排列及波段新高策略，依 registry 的參數定義產生表單並執行篩選。選股 SHALL 接受起訖日期，預設為資料庫最新交易日的單日範圍（資料庫無行情時預設臺北當日）；有效範圍最多 120 個有行情交易日。網站 SHALL 另支援既有桌面端的複合選股模式（均線排列 AND 波段新高），該模式不是回測策略 registry 項目。

#### Scenario: 使用策略與條件篩選
- **WHEN** 使用者選擇策略並送出有效參數
- **THEN** 系統以 `stock-core` 現有策略執行篩選並回傳符合標的

#### Scenario: 依日期區間選股
- **WHEN** 使用者提交有效策略與最多 120 個有行情交易日的起訖範圍
- **THEN** 系統以該範圍執行非同步選股工作並讓使用者查詢結果

#### Scenario: 拒絕超出選股日期上限
- **WHEN** 日期範圍格式無效、起始日晚於結束日、迄日晚於臺北當日或範圍超過 120 個有行情交易日
- **THEN** API 回傳驗證錯誤且不建立選股工作

#### Scenario: 動態列出核心策略
- **WHEN** 使用者開啟策略選擇器
- **THEN** 網站從策略清單 API 顯示目前 `StrategyKind` registry 支援的五種策略及其參數定義

#### Scenario: 執行既有複合選股
- **WHEN** 使用者選擇複合模式並提交有效的均線排列與波段新高參數
- **THEN** 系統以兩個既有策略的 AND 條件產生結果及兩項符合標籤

#### Scenario: 拒絕不合法參數
- **WHEN** 使用者送出缺漏、超出範圍或不支援的策略參數
- **THEN** API 回傳欄位相關驗證錯誤且不執行篩選

### Requirement: 選股結果與理由
每筆網站選股結果 SHALL 包含代號、名稱、交易日期、策略識別與核心提供的符合理由/標籤，並可連至個股分析。

#### Scenario: 顯示選股結果
- **WHEN** 選股請求成功
- **THEN** 結果表格顯示標的、重要數值及策略理由，點選標的可開啟階段二個股分析頁

#### Scenario: 沒有符合標的
- **WHEN** 有效篩選條件沒有符合標的
- **THEN** 網站顯示空結果提示並保留目前篩選條件供使用者調整

### Requirement: 選股頁面狀態
網站 SHALL 清楚呈現執行中、成功、空結果、驗證錯誤及伺服器錯誤狀態。

#### Scenario: 篩選執行中
- **WHEN** 選股請求尚未完成
- **THEN** 介面顯示處理狀態並避免重複送出相同操作

#### Scenario: API 失敗
- **WHEN** API 回報錯誤
- **THEN** 介面顯示可理解的錯誤訊息且不以舊結果冒充此次結果
