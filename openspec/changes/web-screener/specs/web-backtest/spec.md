## Purpose

提供網站使用者以既有策略與歷史資料執行回測，並檢視訊號和績效摘要，讓桌面端的核心回測能力能在瀏覽器操作。

## ADDED Requirements

### Requirement: 網站歷史回測
網站 SHALL 接受策略 registry ID、日期區間、商品類型、策略參數及正數初始資金（預設新臺幣 1,000,000 元），並以既有 `stock-core` 回測與投資組合流程產生結果。回測區間 SHALL 至少涵蓋兩個有行情的交易日；單日訊號查詢由選股/分析功能處理，不計算投資績效。

#### Scenario: 執行有效回測
- **WHEN** 使用者提交有效策略、日期區間與參數
- **THEN** API 立即回傳工作識別碼；回測完成後，使用者可透過工作結果 API 取得該區間的回測摘要及訊號明細

#### Scenario: 回測資料不足或輸入無效
- **WHEN** 日期區間無有效行情或參數驗證失敗
- **THEN** API 回傳明確錯誤或空結果，不偽造績效數字

### Requirement: 回測績效呈現
回測頁 SHALL 呈現訊號、交易明細、每日權益曲線與核心績效欄位。服務 SHALL 依序使用單次 `BacktestEngine::run_range` 產生訊號、`PortfolioSimulator::simulate` 產生交易/權益曲線，再由 `calculate_metrics` 計算績效。核心引擎 SHALL 在保留既有股票優先訊號遍歷順序下，每最多十個交易日檢查取消；不得為取消而分塊呼叫 `run_range`、合併或重排訊號。流程 SHALL 與 CLI 相同：訊號依收盤價成交，每筆買入以當時可用現金買進可購買的整股，不計交易成本，未平倉部位以區間內收盤價估值。年化報酬與 Sharpe 採核心既有 252 交易日年化方式；勝率、報酬與回撤 SHALL 以明確單位呈現。

#### Scenario: 檢視回測結果
- **WHEN** 回測成功完成
- **THEN** 頁面顯示摘要、訊號表格與期間資訊，數值標示其定義和單位

#### Scenario: 回測區間無效或少於兩個交易日
- **WHEN** 日期範圍無效、少於兩個有行情交易日或初始資金非正數
- **THEN** API 回傳欄位驗證錯誤且不輸出績效指標

#### Scenario: 回測績效來源一致
- **WHEN** 網站及 CLI 使用相同資料、策略、日期區間、商品類型與初始資金
- **THEN** 網站回傳的訊號、交易、權益曲線及績效與核心/CLI 計算相同

#### Scenario: 回測失敗
- **WHEN** API 回報回測失敗
- **THEN** 頁面顯示錯誤原因並保留使用者輸入，不顯示前次結果為本次結果

#### Scenario: 取消長區間回測
- **WHEN** 使用者取消正在執行的長區間回測
- **THEN** 核心在最多十個交易日的檢查點停止單次回測，維持原訊號遍歷順序，丟棄不完整結果且不呼叫投資組合模擬器
