## Context

此階段依賴 `web-platform-foundation` 的登入/API/部署，以及 `web-market-analysis` 的股票查詢和分析頁。策略、訊號、投資組合模擬及績效函式已在 `stock-core`；網站只負責驗證輸入、協調執行與呈現。現有回測 registry 有五種策略，桌面端另有均線排列 AND 波段新高複合選股模式。

## Goals / Non-Goals

**Goals:** 移植既有選股與回測的主要瀏覽器工作流程，維持核心結果一致，並建立後續資料維護共用的持久化工作管理器。

**Non-Goals:** 不設計新策略、不更改回測財務模型、不做即時行情；不加入策略編輯器或使用者帳號管理。

## Decisions

- 選股/回測使用本階段建立的單程序工作管理器，API 立即回傳工作 ID，狀態持久化於 SQLite 並以輪詢查詢；第四階段沿用此管理器處理資料寫入工作。
- 長區間選股可分塊處理；回測必須以單次 `BacktestEngine::run_range` 保留核心訊號順序，並擴充核心引擎在原有股票優先遍歷中每最多十個交易日檢查取消。取消時丟棄本次不完整結果，不影響行情資料，也不得重排訊號後交給模擬器。
- `StrategyKind::list/create` 是回測與一般選股的策略清單；將 GPUI 既有複合模式抽出至 `stock-core` 共用選股介面，維持均線排列 AND 波段新高語意，不增加新算法。回測策略清單不含複合模式。
- 回測複用 CLI 流程：`BacktestEngine::run_range` → `PortfolioSimulator::simulate` → `calculate_metrics`。初始資金預設 1,000,000 元且必須為正數；回測至少涵蓋兩個有行情交易日；使用收盤價、整股且不計交易成本的既有假設。
- 結果及工作狀態存於既有應用 SQLite 的工作表；只保留最近 20 個已完成工作結果，較舊結果清除但保留工作狀態，避免工作資料無界成長。
- HTML 表格支援排序/篩選和鍵盤導覽；結果標的連至第二階段分析頁。

## Risks / Trade-offs

- [全市場篩選或長區間回測可能耗時] → 由本階段即採工作 ID/輪詢，不把 HTTP 請求逾時當成取消，也不引進 Redis。
- [桌面 UI 支援的策略參數與核心能力不完全相同] → 以核心 strategy registry/API DTO 作為唯一可用策略清單。
- [績效欄位容易誤讀] → 只顯示引擎提供欄位，附上明確期間、單位及既有計算定義。

## Migration Plan

新增工作狀態資料表 migration，不變更行情資料表。與既有桌面版並行提供，使用同一 `stock-core` 版本；回退僅需回復 Web 映像，不刪除工作紀錄或行情資料。
