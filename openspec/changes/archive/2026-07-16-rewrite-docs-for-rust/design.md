## Context

專案已從 Python/Tkinter 遷移至 Rust/Tauri 架構，但 `docs/` 目錄仍維持 Python 時代的 5 份文件。文件是專案的門面與參考依據，過期文件比沒有文件更危險——它會讓新進開發者學到錯誤的知識。

現有文件問題：
- `cli_usage.md`：指令名稱與行為已不同（Python `twse-crawler` vs Rust `stock-cli`）
- `debugging_guide.md`：API 錯誤碼、資料庫結構都已改變
- `testing_matrix.md`：Python 測試 181 項已不存在
- `CODE_REVIEW_REPORT.md`、`OPENSPEC_REVIEW_FIX_PLAN.md`：完全與現狀無關

## Goals / Non-Goals

**Goals:**
- `docs/` 下的所有文件準確反映 Rust 專案的現狀
- 三群受眾（使用者、開發者、維運者）各自有明確的入口，不需翻閱不相關內容
- 每份文件內容扎實、可獨立閱讀，但透過 `docs/README.md` 串連
- 移除所有 Python 時代的殘留文件

**Non-Goals:**
- 不是撰寫 rustdoc（API 層級的文件留給原始碼中的 `///` 註解）
- 不是完整的教學課程——文件是參考導向，不是教學導向
- 不變更專案建置流程、測試、或原始碼

## Decisions

### 1. 目錄結構：三類分法而非扁平

```
docs/
├── README.md
├── guide/             使用者
├── development/       開發者
└── operations/        維運者
```

**替代方案：扁平 10 個檔案**

| 面向 | 扁平方案 | 三類方案 |
|------|---------|---------|
| 可發現性 | 需要掃描列表找到目標 | 依目錄即可縮小範圍 |
| 擴充性 | 新增檔案可能造成混亂 | 目錄內新增自然 |
| 短名單優勢（<12檔） | ✓ 扁平也夠用 | — |
| 受眾分流 | ✗ 使用者與開發者混雜 | ✓ 各自目錄 |

**決策**：雖然目前文件數不多，但三類分法的組織成本極低（僅多一層目錄），而受眾分流的好處是長期的。選擇三類分法。

### 2. 文件格式：純 Markdown

延續既有 `.md` 格式，不引入 `mdbook`、不引入前端渲染工具。理由：
- 專案規模不需要靜態站點生成器
- 純 Markdown 在任何編輯器與 GitHub 上都可直接閱讀
- 與現有 `README.md`、`CONTRIBUTING.md` 風格一致

### 3. 舊文件處理原則

| 類型 | 處理方式 |
|------|---------|
| CLI 用法 | 保留核心內容（指令結構），改寫所有範例與參數為 stock-cli |
| 排查指南 | 保留通用邏輯（休市判斷、API 格式變動流程），移除 Python DB 操作 |
| 測試矩陣 | 保留 Rust 測試部分，完全移除 Python 測試參考 |
| 歷史審查報告 | 直接刪除 |

### 4. 各文件內容定位

```
docs/README.md
  └─ 專案簡介 + 文件地圖 + 快速連結

guide/
  ├─ 安裝指南.md    # 系統需求、編譯、下載、初次執行
  └─ 命令列工具.md  # stock-cli subcommands + 參數 + 範例

development/
  ├─ 系統架構.md    # Workspace 架構圖、資料流、模組職責
  ├─ 資料庫結構.md  # 三大表格欄位定義、migration 版本歷史
  ├─ 測試.md        # 測試分類、執行方式、新增測試準則
  └─ 資料來源.md    # TWSE/TPEX API 端點、請求/回應格式

operations/
  ├─ 問題排查.md    # 常見錯誤訊息、排查步驟、FAQ
  └─ 自動化排程.md  # cron 排程、批次補檔、資料庫備份
```

## Risks / Trade-offs

- **[風險] 文件與程式碼不同步**：文件是靜態的，而程式碼會持續演進。→ 每份文件開頭標註「最後更新日期」，並在發 PR 時提醒更新相關文件
- **[風險] 文件太少**：比起重寫後反而遺漏重要資訊。→ 設計階段先列出每份文件的綱要，確保覆蓋率
- **[取捨] 沒有生成式文件**：不使用 `mdbook` 或類似工具產生導覽列/全文搜尋。→ 對專案當前規模是合理的簡潔取捨
- **[取捨] 英文還是中文**：專案既有文件與程式碼註解均為繁體中文。→ 保持一致，全部使用 zh-tw
