## Context

詳見 `proposal.md` 與相關 delta 規格。既有日期匯入集中於 `Pipeline::fetch_date`；T86 擷取器與資料庫介面已存在，但彼此尚未接線。自選股切換透過共用 pipeline mutex 存取資料庫，游標與 HUD 狀態則由 `AnalysisView` 管理。

## Goals / Non-Goals

**Goals:**
- 讓回報狀態能反映實際抓取結果，避免將來源錯誤視為休市。
- 以既有資料流和型別修正各項邊界錯誤，並以測試鎖定行為。
- 法人來源錯誤不得影響行情入庫。

**Non-Goals:**
- 建置 TWSE/TPEX 休市日曆。
- 新增自選群組管理介面或 TPEX 法人資料來源。
- 調整既有資料庫 schema。

## Decisions

1. **T86 接入行情日期匯入**：在成功取得 TWSE 行情的日期抓取 T86 並寫入既有法人資料表；T86 網路錯誤記錄為部分匯入狀態，行情仍維持成功。這沿用既有日期補檔路徑，也避免另建一套日期排程。TPEX-only 日期不發出無效的 TWSE T86 請求。
2. **修補失敗以日期摘要回報**：`repair_gaps` 累計來源明確回報的錯誤，整批完成後以錯誤結果回傳日期與訊息；無資料且無來源錯誤仍視為休市略過。UI 既有錯誤分支會保留診斷資料。
3. **序列化自選切換**：先取得 pipeline mutex，再讀取快取並執行資料庫切換；同一把 mutex 使重疊操作依序觀察前一個結果。
4. **保留張數精度**：內部圖表尺度以 `f64` 張數計算，HUD 格式化至少兩位小數；不變更資料庫內的股數欄位。
5. **交互狀態直接通知**：懸停游標座標變更即通知畫布重繪，並在容器離開事件清除懸停狀態。

## Risks / Trade-offs

- **T86 每個 TWSE 行情日期增加一次 HTTP 請求** → 只在 TWSE 行情成功且非空時呼叫，並沿用既有 HTTP 用戶端政策。
- **休市日仍可能被平日診斷列出** → 本次只修正錯誤分類與統計，不引入市場行事曆；介面仍能顯示休市日略過。
- **跨執行緒自選操作可能等待 pipeline mutex** → 這是保證資料庫狀態一致所需的序列化，操作本身只執行少量 SQLite 查詢。
