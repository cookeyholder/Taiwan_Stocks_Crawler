## MODIFIED Requirements

### Requirement: 建立及查詢計算工作
網站 SHALL 以工作識別碼建立選股、回測、單日行情更新、日期區間補檔或券商日報表工作，並提供工作種類、狀態、進度、結果摘要、完整結果與錯誤的查詢 API；工作紀錄及成功結果 SHALL 持久化於應用程式 SQLite，至少保留最近 20 個已完成工作的結果。

#### Scenario: 建立長時間工作
- **WHEN** 使用者提交通過驗證的選股、回測或資料更新請求
- **THEN** API 立即回傳唯一工作識別碼，工作於背景執行且可輪詢狀態

#### Scenario: 查詢工作進度
- **WHEN** 使用者以工作識別碼查詢執行中的工作
- **THEN** 回應包含工作種類、狀態、目前階段及可用進度/摘要

#### Scenario: 取得完成結果
- **WHEN** 使用者查詢仍在保留範圍內的已完成工作結果
- **THEN** API 回傳該工作的結果，且不重新執行工作

#### Scenario: 結果已超過保留數量
- **WHEN** 使用者查詢已超過最近 20 個完成工作保留範圍的結果
- **THEN** API 回報結果已過期，並保留可辨識的工作狀態

### Requirement: 計算工作的互斥與取消
系統 SHALL 同時間只執行一個長時間工作，資料寫入工作 SHALL 使用相同互斥規則；建立工作時若已有長時間工作，系統 SHALL 立即拒絕新工作。可取消工作 SHALL 在計算工作最多十個交易日的安全檢查點，或資料抓取目前來源請求完成後、開始下一個來源請求前取消，回報取消狀態及已完成摘要。回測在單次核心 `run_range` 執行中檢查取消，不得分塊重跑或重排訊號。

#### Scenario: 工作執行時建立另一工作
- **WHEN** 另一個長時間工作已在執行，使用者建立新的選股、回測或資料更新工作
- **THEN** 系統拒絕新工作並回報目前工作識別碼或忙碌狀態

#### Scenario: 取消可取消工作
- **WHEN** 使用者取消仍在執行的選股、回測或資料更新
- **THEN** 系統在安全停止點取消，不回報不完整結果為成功，且保留已完成的資料寫入
