## Purpose

讓個人使用者能從受保護的網站啟動行情同步、區間補檔與券商日報表下載，並安全查看或取消長時間作業，避免重複寫入與請求逾時。

## ADDED Requirements

### Requirement: 建立資料更新作業
網站 SHALL 提供受驗證的 API，供使用者建立單日行情更新、日期區間補檔與券商日報表作業，並將工作加入第三階段的持久化工作管理器。

#### Scenario: 建立有效作業
- **WHEN** 使用者提交有效的作業類型與日期參數
- **THEN** 系統回傳作業識別碼及初始狀態，並在背景開始執行

#### Scenario: 拒絕無效或不支援參數
- **WHEN** 作業類型或日期範圍無效
- **THEN** API 回傳驗證錯誤且不建立作業

#### Scenario: 拒絕過長或含未來日期的補檔範圍
- **WHEN** 使用者提交超過五個日曆年，或起訖日期晚於臺北當日的區間補檔請求
- **THEN** API 回傳驗證錯誤且不建立作業

### Requirement: 長時間作業狀態與進度
作業 API SHALL 提供可輪詢的狀態、進度、完成摘要及錯誤資訊，且前端 SHALL 能區分等待、執行、完整成功、部分失敗、有效無資料、失敗、取消與程序重啟中斷。

#### Scenario: 查看執行中作業
- **WHEN** 使用者以作業 ID 查詢進行中的工作
- **THEN** 回應包含目前階段、處理數量、成功/失敗/略過摘要及可用的進度訊息

#### Scenario: 程序重啟造成工作中斷
- **WHEN** Web 程序於作業完成前停止並重新啟動
- **THEN** 該作業不得被呈現為成功，網站須標示其已中斷或狀態不可恢復

### Requirement: 取消作業與避免重複寫入
網站 SHALL 允許取消支援取消的作業，並 SHALL 遵守第三階段工作管理器的單一長工作互斥規則；資料寫入工作 SHALL 使用該管理器的取消與持久化狀態。

#### Scenario: 取消執行中作業
- **WHEN** 使用者取消一個可取消的作業
- **THEN** 系統停止後續工作、保留已完成資料，並回報取消狀態與完成摘要

#### Scenario: 重複啟動衝突作業
- **WHEN** 有一個 SQLite 寫入作業執行中，使用者再啟動衝突作業
- **THEN** 系統立即拒絕新作業，並清楚說明目前已有作業執行

#### Scenario: 取消區間補檔
- **WHEN** 使用者於某日的來源請求進行中取消日期區間補檔
- **THEN** 系統等目前來源請求完成後，在開始該日下一個來源請求前停止；若已無下一來源，則不開始下一日期，保留已入庫資料並回報已處理區間

### Requirement: 券商日報表日期限制
網站 SHALL 遵守既有 BSR 僅支援臺北當日 16:00 後資料的限制，不得允許使用者將即時來源結果標記為任意歷史日期。市場行情區間補檔 SHALL 逐日使用可取消的 `Pipeline::fetch_date`，並在每個日期及來源請求邊界檢查取消狀態。

#### Scenario: 要求抓取非當日 BSR 資料
- **WHEN** 使用者為券商日報表指定非臺北當日日期
- **THEN** API 拒絕建立作業並說明資料來源限制

#### Scenario: 盤後資料尚未產生
- **WHEN** 使用者在臺北當日 16:00 前建立 BSR 作業
- **THEN** API 拒絕建立作業並說明須於當日 16:00 後再執行

#### Scenario: 成功作業完成
- **WHEN** 核心抓取流程完成並回報成功或部分失敗摘要
- **THEN** 網站顯示實際結果與錯誤數量，不將部分失敗顯示為全數成功

### Requirement: 來源結果明確分類
核心抓取結果 SHALL 以型別分別提供 TWSE 行情、TWSE T86 三大法人資料及 TPEX 行情的資料、有效無資料或來源錯誤狀態；工作管理器不得解析訊息字串判斷成功、休市或部分失敗。完整成功 SHALL 要求所有本次應執行的來源子作業均成功（有資料或有效無資料），任一來源錯誤且至少一個來源有資料時 SHALL 標記部分失敗。

#### Scenario: 所有行情及法人來源皆成功
- **WHEN** TWSE、適用的 T86 與 TPEX 均回傳有效資料或有效無資料，且行情/法人資料寫入成功
- **THEN** 工作摘要標記完整成功並列出各來源匯入筆數及無資料狀態

#### Scenario: 有資料但任一來源失敗
- **WHEN** 至少一個來源的資料成功入庫，而 TWSE、適用的 T86 或 TPEX 任一來源回報網路或解析錯誤
- **THEN** 工作摘要標記部分失敗、保留已入庫資料並明列失敗來源

#### Scenario: 所有來源均有效回報無資料
- **WHEN** TWSE、適用的 T86 與 TPEX 均成功回應但皆無資料
- **THEN** 工作摘要標記有效無資料，不推斷為休市且不將來源錯誤歸類為無資料

#### Scenario: 來源有資料且其餘來源有效無資料
- **WHEN** 一個來源成功匯入行情或法人資料，而其他應執行來源有效回應無資料
- **THEN** 工作摘要標記完整成功並分別列出有資料與無資料的來源

#### Scenario: 來源錯誤且沒有成功資料
- **WHEN** 來源請求或解析失敗且沒有任何行情或法人來源成功提供資料
- **THEN** 工作摘要標記失敗並提供來源錯誤摘要

### Requirement: 上游回應格式驗證
來源解析器 SHALL 驗證 HTTP 成功回應中的來源狀態、必要欄位及資料結構；只有符合已知成功格式的空資料回應才可分類為有效無資料，未知或格式錯誤的回應 SHALL 分類為來源錯誤。

#### Scenario: HTTP 成功但來源格式無效
- **WHEN** 上游回傳 HTTP 成功狀態，但內容缺少必要欄位、表格結構或為未知的來源狀態
- **THEN** 解析器回報來源錯誤，不得將回應分類為有效無資料

#### Scenario: 已知格式的有效無資料回應
- **WHEN** 上游回傳符合該來源已知成功狀態及必要結構的無資料回應
- **THEN** 解析器回報有效無資料，且不將其分類為錯誤

### Requirement: 上游請求速率限制
`HttpClient` SHALL 對同一上游主機的請求開始時間至少間隔一秒，涵蓋一般請求、位元組請求與重試；可重試的 HTTP 429 及其他失敗回應若提供 `Retry-After`，SHALL 等待指定時間後再重試。

#### Scenario: 連續請求同一上游主機
- **WHEN** 工作連續向同一上游主機發出多個請求
- **THEN** 每次請求開始時間至少間隔一秒，避免補檔對上游造成突發流量

#### Scenario: 重試遵守速率限制
- **WHEN** 上游請求失敗並進入重試
- **THEN** 重試遵守同主機最小間隔及可用的 `Retry-After` 時間，HTTP 429 依既定重試次數處理
