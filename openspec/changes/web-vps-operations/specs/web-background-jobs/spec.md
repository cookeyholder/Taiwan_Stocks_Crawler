## ADDED Requirements

### Requirement: 備份工作使用共用工作管理器
手動與排程 SQLite 備份 SHALL 使用第三階段建立的共用工作管理器，持久化工作識別碼、來源、狀態、進度與結果，並透過共用工作 API 查詢。手動備份建立時若管理器忙碌 SHALL 立即拒絕；排程備份遇到忙碌 SHALL 保留每日待辦，於管理器空閒後建立一次工作。服務重新啟動時，未完成的備份工作 SHALL 標記為中斷，不得呈現為成功；只有當日成功的排程備份可視為完成每日排程，手動備份不得取代排程備份。

#### Scenario: 建立並查詢手動備份
- **WHEN** 管理者建立手動備份工作
- **THEN** API 回傳工作識別碼，並可透過共用工作 API 查詢進度與備份結果

#### Scenario: 管理器忙碌時建立手動備份
- **WHEN** 另一個長時間工作執行中且管理者建立手動備份
- **THEN** 系統立即拒絕新工作並回報目前工作忙碌

#### Scenario: 手動備份不取代每日排程備份
- **WHEN** 當日手動備份已成功，但當日排程時刻已到且沒有成功的排程備份
- **THEN** 排程器仍建立或排入當日排程備份工作

#### Scenario: 排程時管理器忙碌
- **WHEN** 到達每日備份時刻但共用工作管理器仍忙碌
- **THEN** 排程器保留一筆當日待辦，並於管理器空閒後建立一次備份工作

#### Scenario: 備份工作執行中重新啟動
- **WHEN** Web 服務重新啟動時備份工作仍未完成
- **THEN** 工作狀態標記為中斷；若當日沒有成功的排程備份，排程器可依排程規則重新建立工作
