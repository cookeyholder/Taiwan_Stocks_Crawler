# 問題排查指南

## 1. 市場休市判斷

### 判斷邏輯

`pipeline::fetch_date()` 同時抓取 TWSE 與 TPEX 資料。若兩者皆無回傳資料，則判定為 `DayType::MarketClosed`。

常見情境：

| 情境 | 判斷方式 |
|------|---------|
| 週末六日 | Pipeline 不特別處理，API 回傳空資料則判定為休市 |
| 國定假日 | API 無當日資料，判定為休市 |
| 颱風假 | API 有回傳但為前一日資料（TWSE JSON API），也在 pipeline 層被視為休市 |
| 網路錯誤 / API 異常 | 回傳 `HttpError`，pipeline 視為錯誤而非休市 |

### market_closed vs source_error

| 情況 | 分類 |
|------|------|
| 非營業日、API 無資料 | 休市（無錯誤） |
| HTTP 連線失敗、逾時 | `HttpError` |
| 回應格式解析失敗 | `HttpError` |

## 2. API 格式變動排查流程

1. **確認錯誤** — 看 pipeline 回傳的錯誤訊息
2. **取得樣本** — 直接以瀏覽器或 curl 存取 API URL，下載原始回應
3. **對照 parser** — 檢查 `fetcher/twse.rs` 或 `fetcher/tpex.rs` 中的對應解析邏輯
4. **更新測試** — 先在單元測試中更新 fixture 資料，再修改 parser
5. **驗收** — `cargo test -p stock-core`

## 3. 資料庫問題

```bash
# 查詢資料庫位置
ls -la market_data.db

# 使用 sqlite3 直接檢查
sqlite3 market_data.db

# 檢查表格是否存在
.tables

# 查看某日各市場筆數
SELECT market_code, count(*) FROM market_quote_core
WHERE trade_date = '2026-06-10' GROUP BY 1;

# 檢查重複資料
SELECT trade_date, market_code, symbol_clean, count(*)
FROM market_quote_core
GROUP BY 1, 2, 3 HAVING count(*) > 1;
```

## 4. HTTP 連線問題

`HttpClient` 實作自動 retry：

- 最多重試 **3 次**
- 使用 **exponential backoff**
- 若持續失敗，請檢查：
  - 網路連線是否正常
  - API 端點是否可達（嘗試以瀏覽器開啟 API URL）
  - 是否被防火牆或 proxy 阻擋
